================================================================================
CodeBrix.LilyPort -- tools/midi2lyprobe/
================================================================================

THE MIDI IMPORTER'S ORACLE HARNESS, built to the same shape as
tools/abcprobe/ -- read that README first; what follows is only what differs.

    gen-midi2ly-fixtures.py   runs LilyPond's OWN midi2ly over the corpus and
                              records what it produced
    MidiProbe/                replays those fixtures through the port's
                              CodeBrix.LilyPort.Importers.MidiImporter

Fixtures land in tests/CodeBrix.LilyPort.Tests/fixtures/midi2ly/ and are also
replayed as assertions by MidiImporterParityTests.

--------------------------------------------------------------------------------
THE CORPUS IS THIS REPOSITORY'S OWN ROUND TRIP
--------------------------------------------------------------------------------

    tools/regression-harness/reference-midi/midi/*.midi     90 files

Those are what the pinned LilyPond engraved from this repo's own MIDI regression
subsuite, so a case here is the whole circle:

    .ly  ->  engine  ->  .midi  ->  midi2ly  ->  .ly

That is a better corpus than the seventy-five files upstream ships for midi2ly,
and it is made of music this port already engraves to the byte, so a case that
breaks is about the importer and nothing else.

⚠ THE BYTES ARE EMBEDDED IN EACH FIXTURE, base64, 29 KB across the whole
corpus. The reference MIDI is regenerated by a script, and a replay that
depended on the state of a generated directory would be a replay of whatever was
last generated. Embedded, the fixture is the recording.

--------------------------------------------------------------------------------
WHAT IS RECORDED
--------------------------------------------------------------------------------

All ninety files with the defaults, and then nine representative files under each
of the nine options that changes the output -- 171 cases. The nine are
lyrics-addlyrics, voice-5, tempo-accel-granularity, key-option, midi-polymeter,
midi-overlapping-notes, quantize-duration, quantize-start and
beat-structure-by-metronome-12-8: between them they reach the lyric path, the
voice layout, a fractional tempo (which is where the exact-rational arithmetic
matters), key and time signatures, note unthreading, both quantisers and the
metronome-derived beat structure.

--------------------------------------------------------------------------------
WHY NOT -q
--------------------------------------------------------------------------------

The opposite of abc2ly's answer, and for the same reason -- read what the switch
actually covers. midi2ly's --quiet suppresses its progress line AND its
excess-voices warning, and that warning is material a caller needs. So the oracle
is run WITHOUT -q and the single progress line ("LY output to `...'...") is
dropped by name in gen-midi2ly-fixtures.py's split_stderr. That one filter is
the only thing between the oracle's stderr and the expected message list.

--------------------------------------------------------------------------------
NOTHING DIVERGES HERE
--------------------------------------------------------------------------------

All 171 cases are byte-identical to what upstream produced. Two things that might
have made that untrue, and did not:

  * The frozen `\version "2.14.0"'. D63 ruled the port writes upstream's own
    frozen number -- it is not the ported release, so rule 16 never governed it.
  * midi2ly's all-notes-off loop, which deletes from the dictionary it walks.
    That shape does raise in python, but create_track routes channel messages to
    a Channel and meta events to the Track, so `pitches' is always empty when the
    branch runs. MEASURED: a MIDI with a hanging note converts fine. Unreachable
    code, left alone -- a fix to unreachable code is a divergence that buys
    nothing. See tools/abcprobe/DIVERGENCES.txt, "NOT DEFECTS".

--------------------------------------------------------------------------------
RUNNING IT
--------------------------------------------------------------------------------

    PYTHONDONTWRITEBYTECODE=1 python3 gen-midi2ly-fixtures.py [<oracle-bin>]
    dotnet run --project tools/midi2lyprobe/MidiProbe -c Release

The generator needs tools/regression-harness/reference-midi/midi to exist; run
tools/regression-harness/generate-midi-reference.sh first if it does not.
